# Zoo

Zoo 是一个面向羽毛球赛事的轻量级瑞士轮管理程序。当前版本固定支持 16 个参赛单位；一个参赛单位既可以是一名单打球员，也可以是一组双打搭档或一支团体队。

## 当前赛制

- 第一轮：16 个参赛单位抽签组成 8 场比赛。
- 后续轮次：优先在相同胜负记录的参赛单位之间配对。
- 避免重赛：配对算法优先安排此前没有交手过的对手。
- 晋级与淘汰：3 胜晋级，3 负淘汰。
- 最多轮次：5 轮，最终 8 个参赛单位晋级、8 个参赛单位淘汰。
- 比赛形式：每轮可配置为一局定胜负、三局两胜或五局三胜；当前只记录胜者，不记录逐局比分。

图示赛程可概括为：

```text
0-0
├─ 1-0 ─┬─ 2-0 ── 3 胜晋级
│       └─ 1-1
└─ 0-1 ─┬─ 1-1
        └─ 0-2 ── 3 负淘汰

2-1 / 1-2 → 3-1 晋级或 1-3 淘汰
2-2       → 3-2 晋级或 2-3 淘汰
```

## 功能

- 创建 16 个参赛单位的单打、双打或团体赛事
- 使用可复现的抽签种子生成首轮对阵
- 自动生成同战绩优先、避免重赛的后续对阵
- 点击参赛单位即可录入或修改胜者
- 自动判断晋级、淘汰和赛事完成状态
- 按胜负记录与 Buchholz 对手分展示实时排名
- 撤回上一轮结算
- 浏览器本机自动保存
- 导入、导出 JSON 赛事存档
- 适配电脑和手机

## 本地运行

需要 Node.js 18 或更高版本，不需要安装第三方依赖。

```bash
npm start
```

然后在浏览器打开 <http://127.0.0.1:4173>。

运行核心规则测试：

```bash
npm test
```

## 配对规则说明

第二轮起，程序使用全局最小成本配对：

1. 大幅惩罚重复交手；
2. 优先匹配相同胜负记录；
3. 同等条件下兼顾初始顺位与由抽签种子产生的稳定随机顺序。

对 16 个参赛单位，程序会在每一轮生成完整的无轮空配对。算法也为后续 8 人版本预留了跨战绩池“浮动配对”的基础，但 8 人模式尚未在界面中开放。

## 目前限制

- 固定 16 个参赛单位。
- 只记录每场胜者，尚未记录每局分数、净胜局或净胜分。
- 只有本机单用户模式，没有账号、云同步、裁判端和大屏端。
- 排名中的对手分用于同战绩展示；正式赛事采用哪种加赛或排名规则，应由竞赛规程明确。
